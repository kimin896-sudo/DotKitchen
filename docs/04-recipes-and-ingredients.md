# 04. 레시피 & 재료 체계

## 요리 차별화 — 4가지 스탯

모든 요리는 아래 4가지 속성으로 차별화됨.

| 스탯 | 의미 | 예시 |
|------|------|------|
| **손질/전처리** | 재료를 썰거나 준비하는 데 걸리는 시간 | 채소 썰기, 고기 손질 |
| **조리/불질** | 렌지·오븐에서 익히는 시간 (대기 필요) | 스테이크 굽기, 찌개 끓이기 |
| **포장/서빙** | 완성 후 즉시 나갈 수 있는지, 추가 단계 필요 여부 | 포장 용기 담기, 플레이팅 |
| **단가·신선도** | 미리 만들어 둘 수 있는지 vs 즉시 조리 필요 | 찌개(사전 준비 가능) vs 스테이크(즉시) |

## 요리 유형별 분류

### 초스피드 / 포장·배달 특화

| 요리 | 카테고리 | 특징 |
|------|----------|------|
| 아메리카노 / 에이드 | 카페 | 전처리 0초, 버튼 즉시 추출. 낮은 단가, 빠른 순환 |
| 프렌치 프라이 / 샌드위치 | 패스트푸드 | 미리 튀겨두거나 바로 포장. 손님 몰릴 때 방어용 |

### 중간 손질 / 균형형

| 요리 | 카테고리 | 특징 |
|------|----------|------|
| 짜장면 / 김치찌개 | 중식·한식 | 소스·국물 사전 준비, 주문 시 면/밥만 → 빠른 출고 |
| 비빔밥 | 한식 | 불 미사용, 재료 3~4가지 각각 손질 → 손 많이 감 |

### 고난도 / 고단가 / 홀 전용

| 요리 | 카테고리 | 특징 |
|------|----------|------|
| 스테이크 / 랍스터 | 양식 | 굽기 + 가니쉬 + 불 조율, 긴 조리, 엄청난 수익 |
| 파르페 / 조각 케이크 | 디저트 | 복잡한 손질, 홀 손님 만족도(평점) 대폭 상승 |

## 재료 체계

### 공통 재료

밀가루, 계란, 우유, 설탕, 버터, 양파, 마늘, 식용유, 소금

### 요리별 재료표

#### 디저트/베이커리

| 요리 | 공통/중복 재료 | 개별/특수 재료 |
|------|----------------|----------------|
| 딸기 케이크 | 밀가루, 계란, 우유, 설탕, 버터 | 딸기 |
| 에그 타르트 | 밀가루, 계란, 우유, 설탕, 버터 | (공통 재료 조합으로 완성) |
| 프렌치 토스트 | 계란, 우유, 설탕, 버터 | 식빵 |

#### 양식/브런치

| 요리 | 공통/중복 재료 | 개별/특수 재료 |
|------|----------------|----------------|
| 토마토 파스타 | 양파, 마늘, 식용유, 소금 | 토마토, 파스타면 |
| 크림 파스타 | 우유, 버터, 양파, 마늘, 소금 | 파스타면, 베이컨 |
| 치즈 피자 | 밀가루, 양파, 식용유, 소금 | 치즈, 토마토소스 |

#### 한식/일식

| 요리 | 공통/중복 재료 | 개별/특수 재료 |
|------|----------------|----------------|
| 제육볶음 | 양파, 마늘, 설탕, 식용유, 소금 | 돼지고기, 고추장 |
| 돈가스 | 밀가루, 계란, 식용유, 소금 | 돼지고기, 빵가루 |
| 함박 스테이크 | 계란, 양파, 마늘, 버터, 소금 | 쇠고기 |
| 새우튀김 | 밀가루, 계란, 식용유, 소금 | 새우 |

## 데이터 관리 권장 구조

레시피·재료·손님 유형은 **ScriptableObject** 또는 **CSV** 테이블로 관리.

```
RecipeData (SO)
├── id, name, category
├── prepTime, cookTime, serveTime
├── price, freshness (사전 준비 가능 여부)
├── ingredients[] (재료 id + 수량)
├── requiredEquipment[] (필요 기구 id)
└── unlockCost (명예 포인트)
```

해금 시스템·밸런스 조정 시 데이터만 수정하면 되도록 설계.
